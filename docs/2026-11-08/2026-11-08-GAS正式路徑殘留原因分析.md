# GAS 正式路徑殘留原因分析

## 現象與原因

功能分支的 `archive_test` 和 `setupProperties()` 仍會將 GAS `FIREBASE_URL` 設為 `/test`。正式切換後，手動歸檔可能改回舊路徑，使後續 `/formal` 驗證失敗；`setupProperties()` 也會清空既有 Firebase Secret。這是本機版本的潛在問題，未在線上觸發驗證。

先前隔離測試以模擬前端請求或替換初始化函式為主，沒有覆蓋實際 `doGet` 手動歸檔分支及 `setupProperties()` 對 Script Properties 的影響。

## 修改摘要

```diff
- 手動歸檔：將 FIREBASE_URL 強制設為 /test，並覆寫試算表及船期設定
+ 手動歸檔：保留現有正式路徑、Secret 與其他設定
- setupProperties：強制設為 /test 並清空 FIREBASE_SECRET
+ setupProperties：缺少 URL 時使用 /formal；保留現有 Secret 和已設定的屬性
+ 錯誤路徑：先拒絕，再執行可能變動屬性的初始化
```

`archive_test` 的 action 名稱保持不變，以相容現有前端。初始化的試算表授權檢查使用現有 `SPREADSHEET_ID`，不固定覆寫為其他試算表。

- `node tests/test_gas_archive.js`：21 個情境通過。
- `node tests/test_gas_conditions.js`：8 個情境通過。
