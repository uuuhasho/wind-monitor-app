## 問題與修正

原流程直接發布 Python 建置出的 public；不同執行身分可能讀不到限制 ACL 的檔案，曾造成 CLI success 但頁面 404。

- `deploy/deploy_hosting.ps1`：僅在 `-Deploy` 時以原生 PowerShell 建立繼承權限的 `runtime/hosting-deploy-<uuid>/site`；只複製 public，拒絕 reparse points、空輸出及讀取錯誤。
- 設定與來源 SHA-256 清單放在 site 外；保留 headers/rewrites，固定專案 newlngship、僅 Hosting。
- `deploy/verify_hosting_stage.js`：以 Node 逐檔列舉與讀取，比對完整路徑、數量、SHA-256；失敗即停止，不呼叫 Firebase。
- Firebase 非零退出碼正常向上傳遞；finally 清除此批暫存。若清理本身失敗，仍報錯，不假報成功。

```diff
- firebase deploy --only hosting
+ node deploy/verify_hosting_stage.js <site> <manifest>
+ firebase deploy --only hosting --project newlngship --config <stage/firebase.json>
```

未放寬既有 ACL、未新增依賴、未改 APP 功能或自動部署政策。預設仍僅建置。
