# 預報圖表與更新鎖修正

日期：2026-10-31。狀態：本機修正與建置完成，尚未發布 Hosting。

## 現象與根因

- 正式頁面唯讀切船檢查捕捉 `Cannot read properties of null (reading 'offsetWidth')`，堆疊在 ECharts 5.5.0 tooltip 的 `getSize` / `_updatePosition`。隔離環境以合成 Firebase 與同版本真實 ECharts 重現 10 次同錯。
- `renderForecastChart()` 的 `setOption(option, true)` 在 tooltip 尚有工作時強制重建元件。只改正常 merge 雖消除錯誤，等待足夠時間後單次切船仍可能顯示上一艘船名。先 `hideTip` 再 merge 同時消除錯誤及舊提示殘留。
- 更新鎖原本只在鎖變動時排定計時器；`.info/serverTimeOffset` 後續校正不會重排。mock-clock 測試重現伺服器時間已超過到期時間、按鈕仍停用。

## 重現前提與執行

兩份前端測試是 Playwright CLI 的 `async page => { ... }` run-code 檔。以 localhost:4177 提供 frontend 資源後執行，測試會攔截／模擬外部服務，不連線正式 RTDB。

```text
playwright-cli.cmd -s=forecast-regression run-code --filename=tests/frontend-echarts.js
playwright-cli.cmd -s=forecast-lease run-code --filename=tests/frontend-isolated.js
```

真實 ECharts 測試先準備 `runtime/echarts-5.5.0.min.js`。公開來源為 APP 現用的 `https://cdn.jsdelivr.net/npm/echarts@5.5.0/dist/echarts.min.js`，SHA-256 `42f8329d989b6f6539dd2b15bbdf0d82025762ac112fbb60dc57b27d7bcf3946`。下載需遵守網路權限；快取不加入 Git，也未新增應用依賴。
