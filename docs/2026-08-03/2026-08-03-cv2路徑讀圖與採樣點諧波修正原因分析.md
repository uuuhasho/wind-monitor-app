## 1. 錯誤現象

1. **中文檔名讀圖失敗**：在 Windows 環境下，當處理檔名或路徑包含中文字元（如 `0613中油_raw.png`）的圖片時，傳統 `cv2.imread(image_path)` 回傳 `None`，引發 `ValueError: Failed to load image for CV2 parsing.`。
2. **採樣點數 2nd Harmonic 誤判**：過去使用 `np.argmax(autocorr[15:45])` 尋找自相關全域最大值 (Global Max) 來推算採樣點距離 `dx`，但在部分風速曲線波動較大的圖表上，二次諧波 (2nd harmonic, lag = 2*dx) 的自相關峰值可能高於基頻 (Fundamental)，導致 `num_points` 被誤算（例如將 33 點圖表誤判為 17 點或 23 點）。

---

## 2. 根因分析

1. **`cv2.imread` Windows Unicode 限制**：OpenCV 底層 `cv2.imread` 的 C++ 實現不支援 Windows Unicode API (ANSI 檔名編碼限制)，當傳入 UTF-8 中文路徑時無法開啟檔案。
   - **底層解法**：先透過 Python `np.fromfile(image_path, dtype=np.uint8)` 讀取二進位 ByteStream，再經由 `cv2.imdecode(..., cv2.IMREAD_COLOR)` 在記憶體中解碼。
2. **自相關全域極值缺點**：
   - 傳統自相關直接在區間取 `argmax`，容易受到波形重複週期的諧波干擾。
   - **底層解法 (Known Format Comparison)**：由於中油預測圖表格式只有固定兩種：33 點（8天）或 23 點（5.5天）。直接從量測到的 `chart_width` 計算 33 點與 23 點對應的期望 lag (`lag_33 = chart_width/32`, `lag_23 = chart_width/22`)，再比較 `autocorr[lag_33]` 與 `autocorr[lag_23]` 的得分。此法完全免疫二次諧波干擾。
