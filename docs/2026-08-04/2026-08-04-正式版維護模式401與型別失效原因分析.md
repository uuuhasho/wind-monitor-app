# 2026-08-04 正式版維護模式失效原因分析與修復紀錄

## 1. 錯誤現象
使用者於 2026-08-04 測試將 Firebase Realtime Database 節點 `/system_status/maintenance` 設定為 `true` 時，前端畫面未出現維護遮罩，後端背景監控與 LINE 告警排程亦未停止。

---

## 2. 根因分析

### 根因一：Firebase Realtime Database 權限拒絕 (401 Unauthorized / PERMISSION_DENIED)
1. **前端 (index.html)**：
   - 監聽 `db.ref('system_status/maintenance').on('value', ...)`。
   - 因 Firebase RTDB Security Rules 未開啟 `/system_status` 的未驗證讀取權限 (`.read: true`)，前端訪客 SDK 遭遇 `PERMISSION_DENIED`。
   - 由於未設置 `errorCallback`，錯誤被靜默拋棄，`successCallback` 未觸發，遮罩無法顯示。
2. **後端 (gs_NV4.7.7.js)**：
   - `isSystemInMaintenance()` 執行 `callFirebase("system_status/maintenance", null, "get")` 時，收到 `401 Unauthorized` (`{"error": "Permission denied"}`)。
   - `safeJsonParse('{"error": "Permission denied"}')` 解析為物件 `{error: "Permission denied"}`。
   - 後端比對 `{error: "Permission denied"} === true` 評估為 `false`，判定系統處於正常運作狀態，背景任務繼續執行。

### 根因二：型別嚴格比對過嚴 (`=== true`)
- 若在 Firebase Console 輸入數值時選用型別為 **String**（例如填入 `"true"`），`"true" === true` 結果為 `false`，導致前後端判定失誤。
