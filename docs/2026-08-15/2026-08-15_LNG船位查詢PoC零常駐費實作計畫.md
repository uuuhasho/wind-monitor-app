# LNG 船位查詢 PoC：零常駐費實作計畫

日期：2026-08-15

## 摘要

- 以 `shadow-fleet-tracker-light` 的 AISStream 接收、IMO/MMSI 對照及位置快取邏輯為參考，不整包導入。
- 新增獨立的 `vessel-position-test` Cloud Run 服務，採 request-based billing、`min-instances=0`、`max-instances=1`；只有使用者按下 Position 時才執行最多 30 秒，平時縮至 0。
- `shadow-fleet-tracker-light` 是事件驅動接收 AIS，原專案每 180 秒重新產生 Folium 地圖，而且已有內建地圖。本案不使用該地圖，改在現有 PWA 以 Leaflet 顯示位置。
- 船名與 IMO 取自 `REF/Vessel details table.xlsx`。AISStream 不能直接用 IMO 作為伺服器端篩選條件，因此首次查詢會從 `ShipStaticData.ImoNumber` 找出 MMSI 並快取；不使用船名模糊猜測。
- 不使用 MINT 帳密、自動登入或瀏覽器爬取。

參考：[AISStream API 文件](https://aisstream.io/documentation.html)

## 實作變更

### 船舶資料與後端

- 將 Excel 的服役中船舶匯出成僅供後端使用的 registry，欄位為 `display_name`、`normalized_name`、`imo`；原始 Excel 不部署至 Firebase Hosting。
- 名稱採 Unicode 正規化、去除首尾與重複空白、忽略大小寫；不做模糊配對。重複名稱、空白或無效 IMO 在匯入階段直接報錯。
- 新服務使用世界範圍 AISStream：
  - 已有 MMSI：以 `FiltersShipMMSI` 精準等待位置訊息。
  - 尚無 MMSI：在本次 30 秒查詢中只監聽 `ShipStaticData`，以 IMO 找 MMSI。
  - 查詢結束後不繼續背景運作；未解析成功顯示「等待船舶識別訊號」，由使用者稍後重試。
- MMSI 對照和最後位置寫入 Firebase RTDB 測試區：
  - `/test/vessel_tracking/registry/{imo}`
  - `/test/vessel_tracking/positions/{imo}`
- AISStream API key 放入 Secret Manager；不寫入程式碼、Excel、Firebase 或前端。
- 位置資料包含緯度、經度、AIS 觀測時間、SOG、COG。10 分鐘內標示為「最新」，超過則標示「歷史位置」並保留確切更新時間。

### API 介面

- `GET /api/v1/vessels/position?ship_name=...`
  - 立即回傳已快取的位置及識別狀態，不連接 AISStream。
- `POST /api/v1/vessels/position`
  - Request body：`{"ship_name":"A 船"}`
  - 最多等待 30 秒取得 MMSI 或最新位置，成功後更新 Firebase 快取。
- 統一回應欄位：
  - `identity_status`: `resolved | pending`
  - `position_status`: `fresh | stale | none`
  - `refresh_status`: `updated | timeout | source_error | not_attempted`
  - `vessel`: 船名、IMO、已解析時的 MMSI
  - `position`: `latitude`、`longitude`、`observed_at`、`sog`、`cog`，無資料時為 `null`
- 不在 registry 的船回傳 HTTP 404；已有另一筆查詢執行時回傳 HTTP 429，避免免費服務被平行請求撐大。

### PWA 操作與地圖

- 在船期表的船名欄加入水平手勢：
  - 使用者將該船列向右滑時，船名略向右移，Position 按鈕由同一欄右側向左平滑出現。
  - 僅允許一列展開；點擊其他位置、反向滑動或開啟另一列時收合。
  - 以水平位移和方向比例判斷手勢，避免干擾既有垂直捲動。
- 按下 Position 後開啟底部資訊面板：
  - 先用 GET 顯示快取資料。
  - 同時用 POST 進行 30 秒更新，顯示倒數或載入狀態。
  - 成功後以 Leaflet 與 OpenStreetMap 顯示標記、座標及更新時間。
  - 地圖圖磚失敗時仍顯示文字座標與時間。
  - 未解析 MMSI、無 AIS 訊號、API 暫停服務分別顯示明確訊息及重試按鈕。
- Position 功能由獨立 feature flag 控制；關閉時維持目前船期表 HTML 和行為。

## 部署與零元控制

- 使用獨立、最小化 Dockerfile，只安裝 Flask、Gunicorn、WebSocket 與 Firebase 必要套件，不包含 LibreOffice、OCR、OpenCV。
- 與現有映像使用相同且固定 digest 的 `python:3.10-slim` 基礎層，目標新增 Artifact Registry 用量不超過 60 MiB；目前約 360 MB，預估總量約 380–420 MB。
- 部署設定：
  - Region：`asia-southeast1`
  - request-based billing
  - 1 vCPU／512 MiB
  - `min-instances=0`
  - `max-instances=1`
  - 35 秒請求 timeout
  - Firebase Hosting `/api/v1/vessels/**` rewrite 至新服務
- 更新清理程序，確認同時保留 `forecast-api-test` 與 `vessel-position-test` 的使用中 digest，只刪除舊版本。
- 部署後量測 Artifact Registry 實際用量；未降至 0.5 GiB 以下前不啟用前端 feature flag。超過 0.5 GiB 不會停機，但會對超額部分計費。
- 30 秒查詢約消耗 30 vCPU-seconds；若 billing account 的 Cloud Run 免費額度未被其他服務用完，理論上每月約可容納數千次個人查詢。設定 `max-instances=1` 與預算警示，但不宣稱 Google 提供絕對零元硬上限。

參考：[Cloud Run 價格](https://cloud.google.com/run/pricing)、[Artifact Registry 價格](https://cloud.google.com/artifact-registry/pricing)

## 測試與驗收

- Excel registry：正常匯入、重複船名、無效 IMO、船期名稱大小寫及空白差異。
- AIS 模擬：IMO 成功解析 MMSI、30 秒未解析、位置成功、來源斷線、錯誤座標、舊資料回退。
- UI：右滑展開、垂直捲動不誤觸、僅一列展開、按鈕動畫、地圖與純文字 fallback。
- 回歸：feature flag 關閉時，既有船期表、Firebase 監聽、風速預報、POB 和調整功能完全不變。
- 先只啟用 2–3 艘測試船；確認命中率、更新時間和遠洋盲區後，再開放整份服役船清單。

## 假設與限制

- 用途是個人開發 PoC，不提供營運 SLA。
- AISStream 是免費 Beta 服務，可能斷線且沒有 SLA；全球範圍代表全球訂閱範圍，不代表遠洋區域一定有即時陸基 AIS。
- 「背景等待」僅發生在使用者啟動的 30 秒查詢期間；不建立付費常駐程序。
- 船舶停泊時可能數分鐘才發送一次位置，因此 30 秒查不到不視為系統故障，介面改顯示最後位置與觀測時間。
