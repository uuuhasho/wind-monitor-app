# 2026-09-19 00Z 預報時間解析錯誤原因分析與修復

**記錄日期**：2026-09-19  
**問題描述**：空軍發布 00Z 起算之 5.5 天 (23 點) 天氣預報時，因本機環境缺乏 Tesseract CLI 執行檔導致 OCR 拋出異常，觸發舊版 Fallback 邏輯強制假設為前一日 12Z，使 App 顯示圖表與 Open-Meteo 陣風融合曲線發生 12 小時嚴重位移。

---

## 一、錯誤現象 (Symptom)

在執行管線分析 00Z 起算之預報圖表（例如 `0918中油`）時：
1. **原始預報特徵**：
   - 右上角標題：`00Z18SEP initial fileld`
   - 底部時間軸標籤：由 `18日 00Z` 起算至 `23日 12Z`，共 23 節點（22 個 6 小時間隔 = 132 小時 = 5.5 天）。
   - 首筆預報時間換算台灣時間（CST, UTC+8）應為：**2026-09-18 08:00:00+08:00**。
2. **修復前 App 錯誤輸出**：
   - 終端機顯示警告：`[Warning] OCR failed to detect initial time. Using fallback logic (Target - 1 day, 12Z).`
   - 誤判起始時間為：`12Z17SEP`，換算台灣時間為 **2026-09-17 20:00:00+08:00**。
   - 時間軸整體**往過去提早了 12 小時**，致使 Open-Meteo 逐時陣風數據與空軍風速預報完全錯位，嚴重影響船舶靠泊與防颱判斷。

---

## 二、根因分析 (Root Cause Analysis)

### 1. 系統環境未安裝 Tesseract CLI，`pytesseract` 靜默拋出異常
- 原程式依賴 `pytesseract` 並寫死指向 `C:\Program Files\Tesseract-OCR\tesseract.exe`。
- 在 Windows 本機環境未安裝該 CLI 工具時，呼叫 `image_to_string()` 直接觸發 `FileNotFoundError`，使 OCR 辨識完全失效。

### 2. 舊版 Fallback 邏輯死鎖於 12Z (Target - 1 day)
- 舊程式碼在 `src/cv2_parser.py` 中如下：
  ```python
  if initial_dt is None:
      current_year = datetime.now().year
      target_dt = datetime.strptime(f"{current_year}{target_date_str}", "%Y%m%d")
      initial_dt = target_dt - timedelta(days=1)
      initial_dt = initial_dt.replace(hour=12, minute=0, second=0)
      initial_date_str = initial_dt.strftime("%HZ%d%b").upper()
  ```
  此處未經任何校驗，直接假設所有預報皆為「前一日的 12Z」，當遇到空軍發布「當日 00Z」之預報時必定發生 12 小時之位移錯誤。

### 3. 缺乏雙重 OCR 與底部時間軸校驗機制
- 空軍圖表底部皆印有明確的 6 小時時間刻度標籤 `(00|06|12|18)`。舊程式僅單純依賴右上角文字，未擷取底部標籤作為 Ground Truth，亦無法在右上角模糊時自動推斷首節點時間與真實預報天數（5.5 天 vs 8 天）。

### 2. 標題被塗銷 / 遮蔽極端情境（Fallback 容錯）驗證
- **情境**：塗銷右上角所有 Initial Time 文字以模擬嚴重 OCR 模糊。
- **輸出紀錄**：
  ```text
  [OCR Notice] Title regex did not match. Raw title text: ''
  [OCR Bottom Axis] Found 23 intervals: ['00', '06', '12', '18'] ... ['00', '06', '12']
  [Fallback Time] Inferred initial time: 00Z18SEP (first_hour=00Z)
  [CV2 Parser] Number of points confirmed by Bottom Axis OCR: 23 points (5.5 days)
  Fallback Initial date detected: 00Z18SEP initial field
  First point: {'date_day': 18, 'hour': 0, 'wind_speed_kt': 10.55}
  ```
- **驗證結論**：即使右上角完全無法辨識，系統依然能藉由底部時間軸開頭的 `00` 標籤，精準推導出 `00Z18SEP` 與 23 點（5.5 天），彻底告別硬編碼 12Z 死鎖。
