5. 什麼時候回復？怎麼回復？

觸發條件：新 GAS 造成正常風速更新／POB 等既有功能異常、抓錯站點或單位、APP 判斷與規格不符、資源缺失或首頁失效。一般資料數值超標不是部署失敗；缺值本身也不是自動回復觸發條件。

情況回復方案回復後驗證
只更新 GAS，Hosting 尚未發布使用發布前保存的 monitor 與 manifest 還原 HEAD；把原 Web App deployment 指回版本 80。兩個動作都要做，不能只改 Web App。HEAD 檔案比對符合備份、deployment 仍是原 ID 且指向 80；觀察正常每分鐘更新恢復。
只有新 APP 有問題，GAS 正常將 Hosting live 回復至發布前的 finalized 版本 4cf8598fda3ae774（以發布前重查結果為準）。可暫留新增 GAS 即時欄位，不回復 RTDB。新 release 指向舊 version，頁面功能恢復。明確通知：舊版 APP 只看風速，不具新浪高／能見度判斷。
GAS 與 APP 都須撤回協調同一維護時段，先回復 Hosting 為舊 UI，再回復 HEAD 與原 Web App 至版本 80；兩步間不宣稱三條件完整生效。三個版本定位都相符，既有功能恢復。向使用者明確回報回到風速單條件版。
Hosting 回復不是刪除新版本：平台會新增一筆 release，重新指向舊內容。回復發布也屬於雲端寫入，必須有授權。只有 Owner／權限檢查不能替代實際執行管道及舊 version 存在性核對。
不回復整個資料庫：發布期間仍可能有真實船期、POB 與風速資料。禁止用發布前 RTDB 快照覆蓋現在資料。回復舊 GAS 後，新欄位可能仍留在 active_status；舊 UI 不讀它們，先保留，另行核准後才清理。
