# 船期列雙擊「位置」按鈕規劃

> 日期：2026-09-28  
> 專案：奶昔 APP  ；首階段限定測試版前端  
> 狀態：討論稿，尚未實作、測試或部署

## 1. 目標與結論

在 PWA 船期表中，使用者對目標船列快速雙擊後，**「位置」按鈕緊接在該列船名右側顯示**，樣式為綠底白字。**只有使用者按下這顆按鈕時**，APP 才複製該列船名並跳轉到船舶追蹤網站。

- 主用：MarineTraffic。
- 備用：VesselFinder。
- MarineTraffic 若不能由穩定網址帶入船名搜尋，第一版以「開啟網站 + 人工貼上已複製船名」為可靠做法。
- 不自動登入、不操控外站搜尋欄、不讀取外站位置資料。
- 不新增位置 API、位置資料儲存、地圖、Cloud Run 瀏覽器或 Artifact Registry 映像。

## 2. 背景與現況

- Firebase Hosting 設定的靜態來源為 `public/`，因此預計修改入口為 `奶昔APP/public/index.html`。
- `public/index.html` 的 `renderScheduleTable()` 產生船期列，列上有 `data-shipname`；目前表格包含日期、船名與速限欄。
- 船期資料由 Firebase RTDB `test/schedule_list` 監聽更新。
- 尚需在實作前確認 `public/index.html` 是否由另一份原始 HTML 產生／同步，以及正式版與測試版的隔離方式。此工作只允許先動測試版，不部署。
- 過往 `docs/2026-07-31/船位置_測試版實作規劃書.md` 描述的是右滑、AIS API、地圖等不同方案；本文件依最新決定改為人工外站查詢便利功能，不沿用其自動擷取架構。

## 3. 已確認的使用者需求

1. 操作目標是 APP 船期表的目標船列。
2. 使用者雙擊／快速點兩下目標列後，「位置」按鈕出現在該列船名右側。
3. 雙擊本身不得複製船名或跳站。
4. 使用者按「位置」後，才複製船名並跳轉。
5. MarineTraffic 為主，VesselFinder 備用。
6. 使用者希望能自動把船名帶入搜尋並搜尋；可以用網站提供且經驗證的搜尋網址，但不以 PWA 腳本跨站填表作為方案。

## 4. 互動規格

### 4.1 雙擊顯示按鈕

- 以事件委派監聽船期表 tbody，從事件目標取得最近的 `tr[data-shipname]`。
- 手機需支援快速點兩下；不要只依賴桌面 `dblclick`，因為部分觸控瀏覽器的行為不同。
- 以同一列、短時間間隔的兩次點擊作判定；實際時間閾值在實機測試中調整。
- 第一次點擊不執行副作用；第二次點擊顯示該列按鈕。
- 同時只顯示一個「位置」按鈕；再雙擊另一列時移至新列。
- 雙擊不複製、不開網站、不請求網路。
- 點擊按鈕不能冒泡成船列點擊／雙擊，避免意外重新切換按鈕。
- 不把此行為做成水平滑動；避免跟表格垂直捲動相衝突。

### 4.2 按下「位置」

1. 從該列取得原始船名並 `trim()`；空船名時顯示錯誤，不導航。
2. 由按鈕使用者手勢觸發剪貼簿寫入。
3. 確認 `navigator.clipboard.writeText(shipName)` 成功後，才在同一分頁開啟預設網站。
4. MarineTraffic 作為預設目的地。
5. 複製失敗時留在 APP，清楚顯示錯誤與重試／手動複製方式；不得顯示「已複製」或無提示地跳走。
6. 同一分頁導航可沿用該瀏覽器分頁的登入狀態；但 PWA 已登入的 MINT 與 MarineTraffic 登入是不同服務，不能假設登入共享。

### 4.3 輔助操作與可及性

- 按鈕使用原生 `<button>`、清楚 accessible name，觸控範圍目標至少 44×44 CSS px。
- 鍵盤使用者應可聚焦列，按 Enter 顯示按鈕，再聚焦並按 Enter 執行。
- 對外站導航只在清楚的按鈕操作之後發生。
- 複製成功／失敗使用可被輔助科技宣讀的狀態文字（例如 `aria-live="polite"`）。

## 5. 外站搜尋策略

### 5.1 MarineTraffic（主用）

MarineTraffic 官方說明：可在 Live Map 的搜尋欄用船名、IMO 或 MMSI 搜尋，從下拉結果選船，也可開啟更多搜尋結果。官方文件未提供已確認的船名搜尋 URL 格式。

**第一版策略：**按「位置」成功複製後開啟 MarineTraffic 的 Live Map／搜尋入口；使用者自行貼上船名並選擇正確船舶。

**可選前置驗證：**若能從一般、合規的人工作業中觀察到網站自行產生的公開搜尋網址，可手動確認該網址在登入／未登入、手機瀏覽器及直接重開時是否穩定。只有穩定且不依賴短效 session/token 時，才考慮把它當直達搜尋連結。這不是必要前置，亦不得逆向私人 API 或模擬網站內部請求。

### 5.2 VesselFinder（備用）

已實際打開並確認下列頁面會依 `name` 參數呈現船名搜尋結果：

```text
https://www.vesselfinder.com/vessels?name={URL-encoded ship name}
```

船名可能重複，搜尋頁只代表候選結果；由使用者人工確認正確船舶。建立 URL 時要使用 `URLSearchParams` 或等價的安全 URL 編碼，不可直接拼接未編碼船名。

### 5.3 操作選擇介面

目前決策以單一「位置」按鈕 + MarineTraffic 預設為主。VesselFinder 的選擇方式仍待確認：

- 方案 A（建議）：按位置直接開 MarineTraffic；VesselFinder 作為失敗時的人工備用連結，可能放在複製失敗／操作提示裡。
- 方案 B：按位置後先顯示「MarineTraffic／VesselFinder」選擇器；使用者再選網站。

需確認是否嚴格要求雙擊後只露出一顆按鈕，以及備用網站入口的 UI 偏好。

## 6. 剪貼簿與導航限制

- `navigator.clipboard.writeText()` 在安全環境（通常 HTTPS）可用，且可能受瀏覽器權限、使用者手勢、PWA 容器與平台版本影響。
- APP 部署在 Firebase Hosting HTTPS，仍須在實際目標手機／PWA 測試剪貼簿成功率。
- 呼叫失敗應捕捉例外，特別是 `NotAllowedError`；不能默默當作成功。
- 避免在非使用者手勢時複製；雙擊只顯示 UI，按鈕才觸發 clipboard write。
- 開站採同一分頁作基線，避免新分頁被 popup blocker 擋住，也方便使用者返回 APP；實機確認返回狀態和瀏覽器行為。
- 若需同時提供一鍵選站，應在「位置」按鈕之後讓使用者選站，並確保複製只發生在最終網站按鈕被按下時，符合「人工明確操作才複製及跳轉」的意圖。

## 7. 範圍界線

### 納入

- 測試版 PWA 船期列雙擊偵測與船名右側位置按鈕。
- 使用者點按後複製目標船名。
- MarineTraffic 主用跳轉與 VesselFinder 備援策略。
- 複製成功、失敗、重試提示與手機／桌面手動驗收。

### 不納入

- 自動登入 Freshmint、MarineTraffic 或 VesselFinder。
- 自動填寫搜尋框、模擬點擊搜尋結果或繞過 CAPTCHA／反自動化措施。
- 抓取外站 DOM/API、讀出 `Last Seen / Lat / Lon` 或自動儲存位置。
- 船舶 IMO/MMSI 自動解析、AIS API、歷史資料、地圖、RTDB 新節點。
- Cloud Run、Firebase rules、Artifact Registry、Dockerfile、requirements、雲端部署或正式版變更。

## 8. 可能檔案與實作注意

預計只修改：

- `public/index.html`：船期列輸出、船名右側按鈕、局部 CSS、事件處理及提示狀態。

需先查明：

- 根目錄 `index.html` 與 `public/index.html` 是否同源或需要同步；Firebase Hosting 的發布來源已確認為 `public/`，但不可未確認就改兩份。
- 測試版資料路徑已有 `test/` 前綴；此功能無資料寫入，因此避免改 Firebase schema／rules。
- 船期列是否已綁定其他 click handler，避免新雙擊辨識干擾現有按鈕／列互動。
- 船名長度與手機寬度的組合；按鈕緊接船名之後，需允許適當換行且不遮擋日期、速限欄。

## 9. 測試與驗收

### 功能驗收

1. 單擊列不複製、不導航、不顯示按鈕。
2. 快速雙擊目標船列，只在該列船名右側顯示綠底白字「位置」。
3. 雙擊另一列時按鈕移動，不殘留兩顆。
4. 點「位置」時剪貼簿精確等於該列船名（只 trim 外側空白，不改船名內部字元）。
5. 複製成功後開啟 MarineTraffic；同分頁導航符合預期。
6. 實測 MarineTraffic 搜尋入口；使用者可貼上船名並人工選對船。
7. VesselFinder 備用 URL 對含空白、`&`、非 ASCII 字元的船名正確 URL encode；結果頁可辨識候選船。
8. 剪貼簿拒絕／API 不可用時，APP 留在原頁並提示重試／人工方式。
9. 按鈕點擊不被列事件當作第二次點擊；重繪船期表後不留下錯誤狀態或重複 listener。

### 裝置與回歸驗收

- Android Chrome PWA（若為主要使用環境）及 iOS Safari／加入主畫面（若有使用）。
- 桌面 Chrome 至少一次，確認桌面雙擊或 Enter 鍵操作。
- 390px 手機寬度，檢查按鈕觸控尺寸、表格可讀性、垂直捲動與點擊辨識。
- Firebase 更新船期表、空資料、長船名、船名含空格等情境。
- 原有排程、速限顯示、船期更新功能無退化。
- 不部署；先由使用者本機／測試網址驗收後再決定下一步。

## 10. 風險與緩解

| 風險 | 緩解 |
|---|---|
| iOS／PWA 不允許程式剪貼簿寫入 | 只在明確按鈕手勢寫入；顯示失敗提示與手動複製方式；實機驗收 |
| 快速雙擊被判斷成頁面縮放或兩次點擊不穩 | 用行動裝置實測時間閾值、阻止只有在必要時的預設行為，不攔截一般垂直捲動 |
| MarineTraffic 搜尋 URL 或 UI 改版 | 第一版只依賴官方 Live Map 搜尋流程，不依賴未文件化 URL；人工貼上可持續使用 |
| 同名船舶造成選錯 | 搜尋結果由人確認；後續可人工用 IMO/MMSI 精確比對，但不在本次自動解析範圍 |
| 位置按鈕擠壓船名或手機表格 | 不新增獨立欄位；窄畫面允許船名與按鈕換行，並以實機確認日期、船名、速限皆可讀 |
