4. 實際驗證結果

本機驗收通過：使用隔離資料與模擬服務，沒有把正式 /test 當作測試資料庫。
  • Python：20 項測試通過。RTDB CAS 競爭、逾時、失敗保留舊預報、force 併發、台灣跨年及新舊融合輸出比對。
  • GAS：12 組 Node VM 情境通過。逐卡失敗／重試、分類列回執失敗、試算表逾時、目標卡衝突、ETag 防並行刪除、POB 風速及換班。
  • Hosting：建置測試及實際 build 通過；缺檔時保留舊 public。資源檢查、主頁及兩個音效網址通過。
  • 前端：Playwright 使用合成 Firebase、ECharts 與 GAS 回應測預報、船期、鎖逾時、開始監控、POB 結束及手動歸檔指令；沒有 JavaScript 錯誤。
  • 部署來源：Python compileall、Node 語法檢查、git diff --check 通過；Cloud Run staging 過濾非必要檔案。影片與旁白 4 檔長度／SHA-256 通過。

5. 部署前審閱與回復

下一步：審閱提交、隔離驗收及回復方案，再另行授權雲端部署。

  1. 記錄 GAS 既有專案、Web App deployment ID、部署版本與觸發器；記錄 Cloud Run revision 及流量。
  2. 備份 RTDB 與試算表。切換時先暫停預報觸發，確認沒有舊版工作；舊版工作不遵守新工作鎖。
  3. 從英文乾淨工作區部署 Cloud Run；機密透過 Secret Manager／環境變數。GAS 需同時升級 HEAD 與既有 Web App deployment。
  4. Hosting 完整建置後部署，核對主頁、簡報、兩個音效網址及 APP 操作流程。
  5. 若驗證失敗，暫停觸發並回切先前 Cloud Run revision、GAS deployment 版本與 Hosting release；保留資料現況供檢查。

不自動清除舊容器映像，保留回復版本；雲端寫入與映像清理須另行審閱。
