🚢 船期表資料消失：原因分析與解決方法

執行日期：2026-10-06 | 影響系統：Google Apps Script (gs_test.js) | 生效環境：GAS HEAD + Web App @79 + GitHub main
🔍 一、原因分析 (為何下午消失？為何改日曆恢復？)
🚨 1. 核心根因：API 裸抓報錯 + 缺乏 Fail-Safe 熔斷機制（雙重漏洞）
  • 防護未同步 (歷史漏洞復發)：2026-08-03 正式版曾修復此問題，但目前主力測試版 gs_test.js 遺漏了 muteHttpExceptions: true。一旦 Google 雲端平台出現瞬時網路波動或 404/500，UrlFetchApp.fetch() 直接拋出 Exception，使船期變為空陣列 []。
  • 缺乏安全保險 (致命一擊)：updateFirebaseScheduleList() 拿到空陣列後，完全未檢查資料長度，直接發送 PUT 請求覆蓋線上 Firebase，把正常的船期表整張抹除。
💡 2. 為何手動更改日曆活動日期後會「瞬間恢復」？
程式中設有日曆事件觸發器 onCalendarOrSheetChange。只要在日曆上拖曳或更改活動，Google Calendar 會立刻推送事件喚醒 GAS 執行同步。此時若網路平台恢復正常，GAS 就能成功抓取日曆資料並重新寫入 Firebase，船期表因而重現。
🎯 3. 修改範圍判定：GCP 需要動嗎？
GCP 完全不需要動。船期的抓取、解析、與 Firebase 的同步 100% 都在 Google Apps Script (gs_test.js) 內部完成。GCP (Cloud Run) 僅負責處理 LINE POB 訊息與氣象風速，與日曆船期表無關。
🛡️ 二、解決方法 (代碼修復、雙重部署與防護 SOP)
🛠️ 1. 代碼雙層防護實施 (gs_test.js)
在 getScheduleList 加入異常靜默與 200 狀態碼檢查；在 updateFirebaseScheduleList 築起 Fail-Safe 熔斷保險（若資料為空，拒絕抹除既有資料）： 
- apiDataRaw = UrlFetchApp.fetch(SHIP_SCHEDULE_API_URL).getContentText();
+ const resp = UrlFetchApp.fetch(SHIP_SCHEDULE_API_URL, { muteHttpExceptions: true });
+ if (resp.getResponseCode() === 200) {
+   apiDataRaw = resp.getContentText();
+ } else {
+   console.warn("抓取日曆 API 非 200 狀態: " + resp.getResponseCode());
+ }

+ // 🛡️ Fail-Safe 熔斷保險：若船期為空，嚴禁抹除 Firebase 既有資料！
+ if (!list || list.length === 0) {
+   console.warn("⚠️ [Fail-Safe] 取得之船期表為空，放棄覆蓋 Firebase！保護既有資料！");
+   return;
+ }
