# 正式版維護模式 (`/system_status/maintenance=true`) 失效真相診斷與修復計畫

## 1. 根本原因精確診斷 (Root Cause Analysis)

首先向您致歉，前一次搜尋時因 `.gitignore` 設定忽略了 `gs_*.js` 與 `.gas/` 目錄，導致工具未掃描到。經使用 PowerShell 直接針對 `gs_NV4.7.7.js` 進行開檔與逐行檢查，**確認 `gs_NV4.7.7.js` 內確實已有 `isSystemInMaintenance()` 函式（第 104, 119, 265, 340 行）**。

在程式碼已存在的情況下，今天測試設定 `maintenance = true` 前後端依然未關閉的**真實根因**如下：

---

### 🚨 關鍵根因一：Firebase 權限阻擋 (401 Unauthorized / PERMISSION_DENIED)
經由 HTTP 請求測試 Firebase Realtime Database 節點：
`https://milkshake-monitor-default-rtdb.asia-southeast1.firebasedatabase.app/system_status/maintenance.json`
回傳結果為：**`HTTP Error 401: Unauthorized` (`{"error": "Permission denied"}`)**。

#### 對前端 (index.html) 的影響：
* 前端（訪客未登入狀態）監聽 `db.ref('system_status/maintenance').on('value', ...)` 時，因 Firebase RTDB Security Rules 預設拒絕未驗證讀取 `/system_status`，SDK 會直接拋出 `PERMISSION_DENIED` 錯誤。
* 由於前端 `on('value', successCallback)` 沒有傳入 `errorCallback`，此錯誤被靜默丟棄，**`successCallback` 完全不會被執行**，導致遮罩 `system-maintenance-overlay` 永遠無法跳出。

#### 對後端 (GAS gs_NV4.7.7.js) 的影響：
* 後端 `isSystemInMaintenance()` 執行 `callFirebase("system_status/maintenance", null, "get")` 時，收到 Firebase 的 401 錯誤回應內文 `{"error": "Permission denied"}`。
* `safeJsonParse('{"error": "Permission denied"}')` 解析為物件 `{error: "Permission denied"}`。
* 後端比對 `{error: "Permission denied"} === true` 結果為 **`false`**！
* 導致 `isSystemInMaintenance()` 判定系統非維護狀態，背景排程與 LINE Webhook 繼續正常運作。

---

### 🚨 關鍵根因二：型別嚴格比對問題 (`=== true`)
* 若在 Firebase Console 輸入時選取型別為 **String** (輸入為 `"true"`)：
  * 前端 `snapshot.val() === true` 比對 `"true" === true` 结果為 `false`。
  * 後端 `safeJsonParse('"true"') === true` 比對 `"true" === true` 结果為 `false`。

---

## 2. 擬議修復與優化方案 (Proposed Implementation Plan)

### Step 1: 修改 Firebase Realtime Database 安全規則 (Security Rules)
於 [Firebase Console (Milkshake-monitor)](https://console.firebase.google.com/) ➔ Realtime Database ➔ 規則 (Rules) 中，將 `system_status` 節點開放讀取權限：

```json
{
  "rules": {
    "system_status": {
      ".read": true,
      ".write": "auth != null"
    },
    ".read": "auth != null",
    ".write": "auth != null"
  }
}
```

### Step 2: 前端容錯與錯誤監聽強化 (`index.html` & `正式版/index.html`)
* 增加型別鬆散容錯（支援 `true`、`"true"`、`"TRUE"`、`1`）。
* 補上 error callback 與 Console 警告，確保權限異常時能正確記錄日誌。

```javascript
// 💡 靜默監聽 Firebase 維護模式狀態 (管道 1: Milkshake-monitor /system_status/maintenance)
db.ref('system_status/maintenance').on('value', (snapshot) => {
    const val = snapshot.val();
    const isMaintenance = val === true || val === 'true' || val === 'TRUE' || val === 1;
    const overlay = document.getElementById('system-maintenance-overlay');
    if (overlay) {
        overlay.style.display = isMaintenance ? 'flex' : 'none';
    }
}, (error) => {
    console.warn("⚠️ Firebase 維護狀態讀取被拒絕 (PERMISSION_DENIED):", error);
});
```

### Step 3: 後端 GAS 容錯與狀態判定強化 (`正式版/gs_NV4.7.7.js` & `正式版/.gas/gs_NV4.7.7.js`)
* 修改 `isSystemInMaintenance()`，使其能容錯處理字串 `"true"`、`"TRUE"` 或 `1`。
* 增加狀態碼與權限異常防護 log。

```javascript
function isSystemInMaintenance() {
  try {
    const res = callFirebase("system_status/maintenance", null, "get");
    if (!res || res.getResponseCode() !== 200) {
      console.warn(`維護模式讀取異常 (HTTP ${res ? res.getResponseCode() : 'NO_RES'})`);
      return false;
    }
    const text = res.getContentText();
    const val = safeJsonParse(text);
    return val === true || val === "true" || val === "TRUE" || val === 1;
  } catch (e) {
    console.error(`維護模式檢查失敗: ${e.message}`);
    return false;
  }
}
```

### Step 4: GAS 自動部署與 GitHub Pages 推播
1. 同步 `正式版/gs_NV4.7.7.js` 與 `正式版/.gas/gs_NV4.7.7.js`。
2. 在 `正式版/.gas/` 目錄執行 `npx clasp push` 與 `npx clasp deploy -i ...`。
3. Commit 並 Push `index.html` 至 GitHub `main` 分支。
