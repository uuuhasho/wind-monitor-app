01｜先看這四件事

  • 日常工作在 main；新增功能時再建立分支。
  • frontend 是前端來源；public 是建置後的網站輸出，不直接修改。
  • runtime、temp 或 archive 名稱不代表可整包刪除，裡面有資料備份及唯一素材。
  • 本次整理本機資料，沒有修改線上 APP 或正式資料。

最常用的發布路徑

frontend
網頁來源→deploy
建置與發布工具→public
Hosting 網站輸出

後端由 backend 經 deploy 的 Cloud Run 工具發布；gas 由 Apps Script 部署。網頁讀取 RTDB，操作由 GAS／後端協作處理。RTDB 的 /test 是正在使用的正式資料路徑。

02｜程式、建置與測試

backend/

Python 後端：app.py 處理 HTTP／LINE 入口，main.py 執行預報流程；src/ 放設定讀取、郵件下載、Word／圖片處理、OCR、預報融合與 RTDB 操作。

保留：Cloud Run 服務來源，requirements.txt 列出 Python 依賴。

frontend/

APP 的 HTML、圖示、PWA manifest 與圖片；presentation/ 放介紹頁、圖片及提示音效。要改畫面與互動，從這裡開始。

保留：Hosting 唯一前端來源。

gas/

monitor.js 是 Google Apps Script 業務邏輯：船期、POB、監控狀態、每日歸檔與觸發器。相關 Apps Script 設定也在此。

保留：程式在雲端執行，本機原始碼需與部署版本區分。

deploy/

Hosting 建置與發布腳本、逐檔雜湊預檢器、Cloud Run 暫存與部署工具、Dockerfile，以及人工 Registry 清理工具。

保留：預設建置；發布需明確部署參數與授權。cleanup_registry.py 不能當自動容量管理器使用。

tests/

Python 與 JavaScript 隔離測試，涵蓋後端、POB、Hosting 建置／發布、GAS 歸檔與觸發器、前端互動。

保留：測試使用模擬服務，不能把 /test 正式資料當測試沙箱。

public/

由 frontend 建置產生的網站目錄。firebase.json 指定 Hosting 從這裡發布，包含 presentation/ 的網站資源。

保留：可重新生成，但目前仍是發布輸出；已由 .gitignore 排除。

根目錄的檔案是做什麼的？

.firebaserc、firebase.json 管理 Firebase 專案與 Hosting；.gitignore、.gcloudignore 控制版控與部署排除。config.json、env.json、service_account.json 是敏感本機設定，本次沒有讀取內容，也不納入同步。

data.json 與 database-debug.log 是本機既有資料／紀錄，本次保留。2026-10-28 架構圖是歷史說明，保留供對照；本文件是本次重新盤點的資料夾說明。
