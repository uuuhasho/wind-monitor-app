# 引水人班表功能：討論總結（第一次）

報告日期：2026-10-23

## 一、功能目標
每月從 Gmail 收到引水人班表 Excel，解析後寫入 Firebase，APP 船期表點船名可看當日工一、工二，手機上點人名可撥電話。23:00 歸檔時把值班人名寫入「歸檔總表」M 欄。

## 二、已確認的決定
| 項目 | 結論 |
|---|---|
| 班表欄位 | A 日期、H 工二（職日員）、I 工一（日班班長），資料從第 6 列起 |
| 電話表 | 工作表 2，D5/E5 起共 19 人。比對前要去掉姓名所有空白 |
| 資料檢查 | 9、10 月班表的工一、工二全部對得到電話。9 月有 14 格空白（已過日期），要跳過 |
| Firebase 路徑 | Demo 階段放 `/test/pilot_schedule`，上線後放根目錄 `/pilot_schedule` |
| 日期 key | `YYYY-MM-DD` |
| 資料結構 | `{gong1:{name,phone}, gong2:{name,phone}}`，不存職稱 |
| 規則 | `pilot_schedule` 設 `.read:true`、`.write:false`。GAS 與 Python 用 DbSecret 寫入，會略過規則，不需開放公開寫入 |
| 電話隱私 | 電話公開可讀 |
| 前端 | 點船名滑出工一、工二；點人名彈出確認；只有手機才有撥打（`tel:`），桌機只顯示 |
| 歸檔 | 在 `archiveAndClearFirebase` 的兩處 `appendRow` 加第 13 個值（M 欄），格式 `工一/工二`，只放姓名。歸檔成功後刪除 `pilot_schedule` 當天資料 |
| 歸檔總表 | M1 已存在「值班引水人」。標題建立程式只有 12 欄，要補第 13 欄 |
| 無船的日子 | 歸檔當天沒有船（沒有列）時不寫入歸檔總表，只刪除 `pilot_schedule` 當天資料 |
| 同日多艘船 | 每列 M 欄都寫同一個值 |
| 電話對照 | 班表上的人一定在電話表內，不會缺漏（解析時仍保留記 log 的防呆） |
| 信件處理 | 每天 16:00 抓主旨含「領港值班表」或「班表」、日期不早於今天的信 |
| 月份並存 | 本月與下個月資料同時存在 Firebase，月份從工作表標題（例如 `115-10月`）取得 |
| 解析方式 | 方案 B：Python（`imaplib` + `openpyxl`），不用 GAS 的 Gmail 授權 |
| Gmail | 班表信與空軍預測信寄到同一個帳號，沿用現有 IMAP 設定 |
| Artifact Registry | 必須維持在 500MB 內，部署走 `deploy_clean.py`（會自動清理舊映像） |

## 三、專案現況發現
- 空軍預測由 Python 抓取：GitHub Actions 每天 15:15 執行 `main.py`，再加 Cloud Scheduler `forecast-trigger-test`（`*/15 12-17 * * *`，Asia/Taipei）呼叫測試版 Cloud Run `/update_forecast`。GAS 沒有 Gmail 權限。
- Cloud Scheduler 在 `asia-southeast1`、`asia-east1`、`us-central1` 只查到上述一個排程。
- 測試版 GAS 在 `test_monitor/gs_test.js`，會把 Firebase 強制指向 `/test`。
- `index.html`、`public/index.html`、`index_test.html` 三份內容相同。
- 歸檔總表：A 欄日期，每艘船一列，不是每天都有列。
